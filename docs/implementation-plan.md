# kids-obby 実装計画書

> 作成日: 2026-06-16 / 根拠: [`research-roblox-mechanics.md`](./research-roblox-mechanics.md)（3票検証済み調査）
> 対象: 5歳の息子向け Roblox風 Webゲーム（obby＋コイン集め＋大きなスライダー）
> スタック: React 19 + TypeScript + Vite + Three.js + R3F + Rapier + ecctrl
> 開発体制: Claude Code セッション単位。**各スプリント完了時に Playwright MCP でClaude自身が実プレイ→デバッグ→自己改善サイクル** を必須実行。

## 0. 方針と優先順位

**優先順位（厳守）**: 品質・保守性・拡張性 ＞ 速度活用 ＞ スコープ削減 ＞ 納期延長 ＞ 近道・フォールバック。
近道（`any`逃げ / テスト省略 / 設計逸脱）は第一選択肢にしない。工数オーバーが見えたら勝手に近道せず3択（§5）を提示。

**スコープ（5歳向け安全設計・既定）**: シングルプレイ・チャットなし・課金なし・敵なし・ゲームオーバーなし。
調査の指摘どおり、マルチプレイ・安全モデレーション・経済圏は自作では標準で付かない → **まず一人で楽しい体験**を作り切る。マルチプレイは将来の別ロードマップ（§7）。

**設計の北極星（調査より）**:
- **報酬ループ**: `行動（集める/すべる）→ 即時フィードバック（音・光）→ 進行（カウント/ごほうび）→ くりかえし`。
- **ジューシーなフィードバック**（潰れる/膨らむ/光る＋ポンッ音）は子供の没入・自信に効く（査読研究の裏付けあり※対象は大人）。**最優先で入れる**。
- obby は「手作りセクションをならべる」方式（Tower of Hell型）。真の手続き生成より、まず良いセクションを数個作る。

## 3. 自動プレイテストの仕組み（Playwright MCP）

`window.__game` でゲーム状態を機械可読に露出し、目視＋数値で検証する。

- `getState()` → `{ coins, totalCoins, playerPos, isOnGround, isMoving, fps }`
- `teleport(x,y,z)` → 任意地点へ移動（コイン取得・着地などの再現に使用）
- `setMovement({...})` → プログラムから操作（テスト補助）
- 実入力パスの検証: `window.dispatchEvent(new KeyboardEvent('keydown',{code:'KeyW'}))` 等で**実キー入力経由**でも動くことを確認（合成イベントでも drei KeyboardControls → setMovement の経路を通る）。

**毎スプリントの手順**: 起動 → `browser_console_messages(error)` で0確認 → `getState()` で受け入れ基準を数値判定 → 実キー入力で挙動確認 → `browser_take_screenshot` で見た目確認 → FPS確認。

> 既知の無害警告（three/rapier/ecctrl 由来の deprecation 3件）は除外して判定。

## 4. 自己改善サイクル（バグ・低再現性への対応）

```

  2. 修正
  3. tsc/build を通す

```

## 5. 工数オーバー時の3択（近道を勝手に選ばない）

- **[A] 品質維持 + 納期延長（推奨）**
- **[B] スコープ削減**（機能を後続スプリントへ後送り。例: スライダー物理が難航 → まず歩いて降りられる緩い坂にし、つるつる物理は別スプリント）
- **[C] 近道許容（非推奨）**（犠牲箇所を具体的に明示）

## 6. スプリント詳細

### S1 ジューシー化（音・光・パーティクル）〔1.5・最優先級・並列可〕
- **目的**: 調査の最重要レバー。集める/ジャンプ/着地/クリアに**即時の音・光・動き**を付け、5歳の「楽しい！」を最大化。
- **作業**: コイン取得音（ポンッ）・取得時のキラキラ（パーティクル/スケールポップ）・ジャンプ/着地音・コイン取得でカウンターが弾む・全取得で紙吹雪と音。Web Audio または `<PositionalAudio>`。過剰演出は避ける（調査の注意）。
- **受け入れ基準**: 取得時に音が鳴る（`getState`で取得検出＋音イベント発火フラグ）・視覚エフェクトが出る（スクショ）・fps劣化なし。

### S2 スライダー物理チューニング〔1・並列可〕
- **目的**: 息子の本命「大きなスライダー」を**本当にすべる**ように。
- **作業**: ecctrl の `slopeMaxAngle`/摩擦/スライダー角度を調整し、上に乗ると自動で滑り降りる挙動に。滑走スピードと安全な着地。必要なら専用の「すべり面」フラグ。
- **受け入れ基準**: スライダー上部に置くと下まで滑り降りる（`teleport`後に時間経過で `playerPos` が着地点へ移動）・引っかからない・吹っ飛ばない。

### S3 レベル/進行（チェックポイント・スタート/ゴール・タイマー）〔1.5・順次の起点〕
- **目的**: 「目標と達成感」。obby に始点・終点・途中復帰点を与える。
- **作業**: スタート地点、ゴール（旗/ゲート）、チェックポイント（触れると復帰位置更新＝Roblox obbyの定石）、落下時はCPへ戻す（落下ダメージなし）、任意でやさしいタイマー/ベストタイム。
- **受け入れ基準**: CP通過で復帰位置更新（`getState`で確認）・落下→CP復帰・ゴールでクリア演出。

### S4 モバイル操作（バーチャルスティック/ボタン）〔1・並列可〕
- **目的**: タブレットで息子が遊べるように。ecctrl の `input`（Joystick/VirtualButton）を活用。
- **作業**: 画面に大きなスティック＋ジャンプボタン。タッチで操作。`setMovement` 経由で接続。
- **受け入れ基準**: タッチ操作で移動・ジャンプ（タッチイベント注入で確認）・タブレット幅で崩れない。

### S5 コンテンツ拡充（セクション・ごほうび）〔2・S3に依存〕
- **目的**: 飽きずに遊べる量。Tower of Hell型に**手作りセクションを増やす**。
- **作業**: 動く床・回る障害物・ジャンプ台・複数スライダー等のセクションを `level.ts` 拡張で追加。ごほうび（宝箱・キャラの色/帽子の着せ替え＝自己表現）。
- **受け入れ基準**: 複数セクションをクリアして進める・ごほうびが反映される。

### S6 セーブ＆仕上げ（保存・タイトル/クリア演出）〔1・順次〕
- **目的**: 続きから遊べる・始まりと終わりの満足感。
- **作業**: 進捗（集めたコイン/開放セクション/着せ替え）を localStorage 保存・復元。タイトル画面、クリア画面。
- **受け入れ基準**: リロードで進捗復元（`getState`一致）・タイトル/クリアが出る。
